# NAnnersVRhub 0.5.1 — installation and upgrades

Final source build, promoted from the accepted installer candidate.

## Install

Requires Linux, Python 3.11+ and working PySide6 in the Python used to install.
On CachyOS/Arch, install the distribution binding if needed:

```fish
sudo pacman -S pyside6
```

After downloading:

```fish
unzip -n ~/Downloads/NAnnersVRhub-0.5.1-source.zip -d ~/Downloads
and cd ~/Downloads/NAnnersVRhub-0.5.1
and python install.py
```

The Hub installer needs no sudo, pip, network access or shell-profile changes.
It checks Python/Qt, the icon and all four recipes before activation.
`python install.py --check` checks dependencies/resources without installing.

Open **NAnnersVRhub** from the application menu or run:

```fish
~/.local/bin/nannersvrhub
```

If `~/.local/bin` is already on PATH, `nannersvrhub` works directly. Otherwise,
the optional fish command `fish_add_path ~/.local/bin` enables the short names.
The menu shortcut uses an absolute path and does not depend on PATH.

The installed app is independent of its extracted source folder. After desktop
testing, that new source folder can be moved or removed. Keep older folders
while Steam launch options still reference their guards.

## Files and data

| Location | Purpose |
| --- | --- |
| `~/.local/share/nannersvrhub/releases/` | Complete versioned app copies with recipes and icon |
| `~/.local/share/nannersvrhub/bin/` | Stable app, management and guard scripts |
| `~/.local/share/nannersvrhub/installation.json` | Active/previous app version and managed-file inventory |
| `~/.local/bin/nannersvrhub`, `nannersvrhub-manage`, `nannersvrhub-check` | Links to the stable scripts |
| `~/.local/share/applications/io.github.BananaNanners.NAnnersVRhub.desktop` | Application-menu shortcut |
| Existing `~/.local/share/vrhub/` | Mod records, gameplay history, backups and logs; preserved in place |

An absolute `XDG_DATA_HOME` changes app and desktop-shortcut locations. It does
not relocate existing Hub state/history. `VRHUB_STATE` retains its existing
meaning; gameplay history follows its parent directory.

No game files, mods, Proton prefixes, Steam options or runtime settings are
rewritten by the installer. An unrelated or manually edited conflicting
launcher/desktop file stops installation rather than being overwritten.

## Upgrade

Close the Hub, extract a newer source ZIP, then run **that folder's**
`python install.py`. The new app is checked and copied before switching one
active-version record. A failed preparation leaves the previous version
selected. Earlier app copies remain available.

Alternatively, point the installed manager at an extracted new source folder:

```fish
~/.local/bin/nannersvrhub-manage install --source /absolute/path/to/new/source
```

This is an explicit local upgrade workflow. Automatic release downloads and
in-app Hub update buttons are outside this release. Existing game-mod update checks
keep their existing purpose.

## Status and rollback

```fish
~/.local/bin/nannersvrhub-manage status
~/.local/bin/nannersvrhub-manage rollback
```

Rollback requires a previous **managed** installation; it checks that copy and
dependencies before switching. Running rollback again switches back to the
other version. It restores app code/resources, without rewinding saved tests,
mod records, game files or other user data. Old source folders are not
automatically imported as rollback versions.

The independent manager can select an intact previous version even if the
active app import is broken. Corrupt installation records and changed release
files are reported and preserved. If the selected Python is removed or loses
PySide6, rerun the source installer with a working Python/PySide6 installation.

## Steam guard

New launch options generated by the managed Hub use the stable guard at
`~/.local/share/nannersvrhub/bin/nannersvrhub-check` (or the chosen app root).
That path survives upgrades and rollback. Existing Steam options are not
rewritten: compare the game's full Hub-generated options before changing an
old guard path. Keep its original folder until that review is complete.

The guard retains the earlier policy: verify exit 1 blocks launch; an
unavailable/broken checker allows the game command to continue.
`VRHUB_SKIP_CHECK=1` remains an explicit bypass.

## Packaging and desktop acceptance

Recipes now live in `vrhub/recipes/`. Source startup and regular non-editable
wheels contain all four recipes and the icon. Wheels provide the app, CLI,
guard and manager entry points. The per-user installer is the recommended
desktop workflow; it uses existing Python/PySide6 instead of installing Qt.

1. Run `python install.py --check`, then `python install.py`.
2. Open the application-menu entry; confirm **0.5.1**, all four games and
   saved tests. Close it, rename the new extracted source folder, and open the
   menu entry again.
3. Review the generated Cyberpunk Steam guard path. Compare complete options
   before editing a working configuration.
4. Report any error exactly as shown. Isolated automated checks do not replace
   your KDE desktop acceptance or a new live gameplay test.

References: [setuptools package data](https://setuptools.pypa.io/en/stable/userguide/datafiles.html)
and [desktop-entry specification](https://specifications.freedesktop.org/desktop-entry/latest-single/).
